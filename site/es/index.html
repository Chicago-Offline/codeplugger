Programar una radio debería ser una compilación, no una sesión de CPS.

codeplugger combina datos de RF compartidos con tu perfil bajo control de versiones para compilar un codeplug validado y neutral de radio. Expórtalo, o escríbelo directamente en una radio compatible.

Cómo funciona

Los hechos y las preferencias se mantienen separados. Los datos de RF describen lo que existe; un perfil describe lo que quieres en una radio concreta. Todo lo intermedio es determinista y revisable.

Datos SSRF

Planes de canales, repetidores y talkgroups públicos de SSRF-Lite, combinados con capas compartidas o privadas por ID de registro estable.

Perfil

Tu política en YAML: qué asignaciones, en qué orden, en qué zonas, con listas de escaneo, grupos RX, contactos y ajustes de la radio. Los perfiles pueden heredar unos de otros.

Resolver y validar

codeplugger une las entradas y comprueba cada canal contra las capacidades de la radio de destino: bandas, modos, longitud de nombres, límites de zonas y listas, capacidad dependiente del firmware.

Exportar o programar

Exporta CHIRP CSV o qdmr YAML; aplica un perfil a una línea base P4 decodificada para TOML; o usa un backend con confirmación para escribir en una radio compatible.

Codeplugs comunitarios precompilados

CI los compila a partir de perfiles comunitarios públicos y datos de RF a medida que cambian las fuentes, y luego publica archivos de importación, referencias imprimibles y sumas de verificación SHA-256. No hace falta instalar codeplugger.

CHIRP CSV

Canales FM analógicos y AM de solo recepción en el orden del perfil, comprobados contra los límites de la radio. Importa y carga en CHIRP donde exista un controlador, o usa chirp-writer en las radios compatibles.

qdmr YAML

Codeplug extensible de qdmr con zonas, listas de escaneo, listas de grupos RX, contactos y varios IDs DMR. Los ajustes nativos de la radio pasan a través de extensions.qdmr.

p64tool TOML

Se aplica sobre una línea base de p64tool decode para que los ajustes no tocados sobrevivan, y luego se vuelve a codificar para la P4.

plan benlink

Un plan de canales declarativo para portátiles con protocolo Benshi, que no tienen CPS de escritorio ni controlador CHIRP: la única vía de entrada es Bluetooth. Las zonas se asignan a las regiones de la radio, y las regiones que el plan omite nunca se escriben.

Escritura directa

Las escrituras requieren confirmación explícita y comprobaciones de seguridad propias de cada backend. La copia de seguridad y la relectura varían según el backend; las operaciones pueden registrarse. Backends: dmrconf, p64tool, chirp-writer y benlink por Bluetooth.

Planificado: ampliar la cobertura de radios y formatos de exportación sin cambiar la resolución central de perfiles.

Funciones

Hecho para quienes mantienen más de una radio coherente y quieren saber exactamente qué entró en cada una.

Compilaciones deterministas

Las mismas entradas siempre producen el mismo codeplug, hasta un SHA-256 estable. Los archivos generados son artefactos desechables, nunca una fuente de datos.

Validación de capacidades

Bandas, rangos TX frente a solo RX, modos, ancho de banda, longitud de nombres, límites de zonas y listas, y capacidad de contactos dependiente del firmware, clasificados como aviso / advertencia / crítico, con todos los críticos informados en una sola ejecución.

Escrituras con confirmación

Confirmación explícita, comprobaciones de identidad propias de cada backend y registros de escritura; verificación previa y relectura donde esté disponible.

Zonas, listas de escaneo, grupos RX, contactos

Los talkgroups son hechos SSRF; la pertenencia y el contacto TX, grupo RX y lista de escaneo por asignación son política del perfil, todo aplicado contra los límites de la radio.

Herencia de perfiles

Comparte un perfil base y deriva variantes con extends, zones_only y omit_zones. Un perfil base que no nombra ninguna radio es reutilizable en cualquier radio con capacidad para él. Revisa el resultado combinado con --print-merged-profile.

IDs DMR de identidad múltiple

Una instancia de radio puede llevar varios IDs DMR; los perfiles vinculan uno por zona o por asignación y los exportadores emiten solo las identidades realmente usadas.

Registro de flota y simulación

Un registro de instancias asocia radios físicas a perfiles. codeplugger-fleet resuelve y valida cada radio e informa de su estado antes de escribir nada.

Hechos de canal derivados

Ancho de banda a partir del designador de emisión de la UIT, modo AM para asignaciones de banda aérea de solo recepción, nombres de pantalla sobrescritos desde capas.

Artefactos de referencia

Referencias de canales en HTML y Markdown más registros de operación por instancia de radio, para que lo que hay en la radio esté siempre documentado.

Extensiones con espacio de nombres

Los ajustes nativos de cada exportador viven bajo extensions.<backend> a nivel de perfil o de asignación, manteniendo el esquema central neutral de radio.

Cómo fluyen los datos

Los datos de RF públicos y las capas alimentan una compilación basada en perfiles; exporta un archivo o programa una radio compatible.

Ecosistema

codeplugger se sitúa entre los datos de RF abiertos y las herramientas que ya hablan con las radios.

SSRF-Lite

YAML autoritativo y legible para planes de canales, repetidores, estaciones y talkgroups. Explóralo en línea.

chioff-ssrf-shared

Canales GMRS y MURS reales de la red comunitaria de Chicago Offline, en capa sobre SSRF-Lite.

chioff-codeplugger-profiles-shared

Perfiles listos para usar que seleccionan la red comunitaria compartida para cada radio compatible.

rf-survey

Estudio de RF basado en SDR que valida los registros de SSRF-Lite con observaciones reales: la evidencia detrás de la confianza en cada canal.

qdmr / dmrconf

Programación DMR de código abierto. codeplugger emite su YAML extensible y maneja dmrconf para la DM-32.

CHIRP

La interfaz de carga para radios analógicas. codeplugger produce CSV compatible con CHIRP.

Chicago Offline

Comunicaciones resilientes y de propiedad comunitaria para el área de Chicago: radioafición, GMRS/MURS, DMR y malla LoRa.

Inicio rápido

Clona codeplugger y usa uv. La instalación trae sus propios datos de RF, así que un caso de uso no necesita nada más; para tus propios perfiles conviene tener ssrf-lite y un repositorio de perfiles clonados al lado.

Programar una radio nueva

# qué es compatible, y qué puede ir en cada radio
uv run codeplugger radios
uv run codeplugger use-cases

# compilar, sin tocar el hardware
uv run codeplugger build \
  --radio baofeng_bf888s --use-case gmrs

# o los canales de un grupo comunitario, por nombre
uv run codeplugger build \
  --radio baofeng_bf888s --profile chioff

# luego escribirlo, con la confirmación del backend
uv run codeplugger program \
  --radio baofeng_bf888s --use-case gmrs \
  --port /dev/cu.usbserial-10 --confirm

Validar un perfil

uv run codeplugger-profile ruta/al/perfil.yml \
  --ssrf-root ../ssrf-lite/ssrf \
  --ssrf-root ../chioff-ssrf-shared/ssrf

Exportar para una radio

# radios analógicas: importar en CHIRP
uv run codeplugger-profile perfil.yml \
  --ssrf-root ../ssrf-lite/ssrf \
  --output-format chirp-csv > salida.csv

# DM-32: qdmr YAML, luego escribir con dmrconf
uv run codeplugger-profile perfil.yml \
  --ssrf-root ../ssrf-lite/ssrf \
  --output-format qdmr-yaml > codeplug.yaml

Comprobar toda la flota

uv run codeplugger-fleet \
  --instance-registry ../mis-perfiles/instances.yml \
  --profiles-root ../mis-perfiles/profiles \
  --ssrf-root ../ssrf-lite/ssrf
